# 1.6 → 1.7 应用内升级验收

2026-11-08，Asia/Taipei。本机原版 `/Applications/EyeBreak.app` 在经用户明确同意迁移更新源后，完成 Sparkle 应用内下载、签名验证、安装和自动重启，最终为 **1.7（66）**。没有手动复制新版 App、修改旧版二进制或关闭签名验证。

## 原地址故障及证据边界

- 原 feed：`https://github.com/yauyy/EyeBreak/releases/latest/download/appcast.xml`。
- 原地址先返回 302；跳转到 `/releases/download/v1.7/appcast.xml` 后返回 HTTP 504。原 DMG 的 Release 下载路径也曾返回 504。
- 原版 1.6 的 Sparkle 日志记录了获取 feed 和下载 DMG 的 504，与用户看到的两种错误一致。
- 17:46 的复查中，TLS 证书验证成功，504 响应含 `x-github-request-id: 690D:27EB62:E7EC69:1148EC3:6AF044E7` 及 `x-github-edge-region: westus3`。这指向 GitHub 分发路径的服务端超时，仍不足以确定其内部故障组件。
- 多个代理节点及 DIRECT 的探测均失败；没有修改系统网络设置、代理选择或安全校验。不能把同机探测等同于多个独立网络的全面验证，也不能宣称 GitHub 全球故障。
- GitHub API 可以读取 Release 资产；同仓库 Raw 通道的 feed 和完整 DMG 实测 HTTP 200。

**原 URL 未确认恢复。** 本次通过的路径为“迁移更新源后升级”，不是原地址原样恢复。

## 迁移范围

在正常退出原版 1.6 后，仅新增其 sandbox 偏好中的 `SUFeedURL`：

```text
https://raw.githubusercontent.com/yauyy/EyeBreak/refs/heads/feature/ymy/update-channel/updates/appcast.xml
```

偏好文件为 `~/Library/Containers/com.yau.EyeBreak/Data/Library/Preferences/com.yau.EyeBreak.plist`。迁移前该键不存在；原程序的 SHA-256 在迁移前后相同：

```text
c782543efa0ec7c37fb5ed49134c24a160a2d7f3e18b6aad072625a9e67dea85
```

本机备份保存在 `/tmp/eyebreak-upgrade-verification/`，包含偏好备份、版本与二进制校验、迁移记录、Sparkle 日志。个人设置和统计数据未上传到仓库。

数据比较基线为正常退出原版后保存的 `preferences-before-migration.plist`；`network-probe-174626.txt` 保存了工具实测 TLS 与 HTTP 响应的摘录。

该偏好会继续覆盖升级后 App 的内置地址。1.7 安装包内置地址仍为原 Release feed；未执行迁移的其他旧客户端不会自动得知新地址。分发分支必须持续维护，不能删除或改名。

其他用户若遇到同样的 504，并决定迁移至该通道，可先从菜单正常退出 EyeBreak，再执行以下命令，重新打开原 App 后使用“检查更新”：

```sh
defaults -container com.yau.EyeBreak write com.yau.EyeBreak SUFeedURL -string 'https://raw.githubusercontent.com/yauyy/EyeBreak/refs/heads/feature/ymy/update-channel/updates/appcast.xml'
```

恢复内置更新源时，正常退出 App 后删除这一个偏好即可；原地址未恢复期间不要撤销已生效的迁移：

```sh
defaults -container com.yau.EyeBreak delete com.yau.EyeBreak SUFeedURL
```
