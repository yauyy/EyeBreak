# 连环提醒技术 PRD

状态：已实现，自动验证通过；真实合盖/跨日人工验收待执行 · 更新：2026-11-08 · 规模：M（新增独立调度、设置和提醒展示）

范围：EyeBreak macOS App。基线：`main` / `22fe496`，开始时工作区无改动。本文件为随仓库保存的持久需求，入口见 [迭代清单](../ROADMAP.md)。

## 概览

新增通用的“连环提醒”，用于一件事情之后按固定间隔连续提醒。用户在“菜单栏 → 设置 → 连环提醒”创建一组每日计划，例如主提醒每天 08:00，后续分别间隔 5 分钟、10 分钟，实际提醒时间为 08:00、08:05、08:15。内容由用户填写，可用于日常事项、用药安排、烹饪等。

用户已确认：直接实现并验证；所有后续提醒必须严格早于下一次主提醒，相等也不允许。时间按主提醒的计划时间累计，点击确认不会改变下一步的时间。

本次支持多组每日计划，以及创建、编辑、启停、删除和本地保存。新建默认主时间为 08:00，首次使用为空列表；不自动建立或开启任何个人事项。当前不扩展为每周、一次性、云端同步或按用户完成时间推进的计划。

| 需求点 | 基线现状 | 本次差异 |
| --- | --- | --- |
| 固定主时间与连续间隔 | 仅有专注、休息、暂停状态机 | 新增独立每日调度，不依赖护眼倒计时 |
| 正常入口 | 设置分区包含通用、休息、工作时段、成就、关于 | 新增连环提醒分区，本机用户均可使用，无账号或额外授权 |
| 跨轮兜底 | 无父子闹钟模型 | 保存校验与运行时检查，最后一步不得进入下一轮 |
| 提醒呈现 | 右上角常驻护眼面板与系统音效 | 独立左上角事项面板，沿用提示音偏好 |

## 一、模块划分与功能描述

| 编号 | 功能 | 行为 |
| --- | --- | --- |
| F1 | 计划管理 | 名称即主提醒内容；每日时、分；启用状态；按顺序排列的后续提醒，每步包含内容和距上一步的分钟数 |
| F2 | 时间与校验 | 每步必须为正整数分钟；累计间隔须小于下一次主时间与本次主时间之差；空内容、非法时间、溢出均拒绝 |
| F3 | 独立调度 | 根据实际日期计算到期时间；护眼开始、暂停、工作时段、离开、会议及全屏规则均不改变事项计划 |
| F4 | 提醒与恢复 | 常驻面板显示原计划时间；同一组新提醒替换前一条，不同组可同时保留；确认只关闭该条 |
| F5 | 本地保存 | 保存计划、生效时间、调度进度和待确认消息；重启恢复，已提示的消息不重复响铃 |

### 时间规则与异常处理

1. 子提醒时间为 `本轮主时间 + 从第一步至该步的累计间隔`。例如 08:00 + 5 + 10 分钟 = 08:15，不是 08:10，也不从点击确认后重新计时。
2. 普通 24 小时周期最多累计 1439 分钟，1440 分钟或以上拒绝；每一步单独合法但累加超界同样拒绝。允许跨午夜，例如 23:55 + 10 分钟 = 次日 00:05。
3. 每日主时间遵循本机时区的日历。下一次主提醒不能用固定加 86400 秒替代。保存时检查未来一年的最短实际周期，避免夏令时短日重叠；运行时按本轮的实际边界复核。时区变动后重新计算，不能因旧配置绕过边界。
4. 新建、修改或重新启用后，只跳过此刻之前的步骤，本轮尚未到点的步骤照常提醒（2026-11-11 修正：原先整轮跳过，导致主时间刚过时保存，当天后续提醒全部不弹）。修改会取消本轮待确认事项。停用和删除立即取消该组待确认及后续调度。
5. App 退出或电脑睡眠时无法准点弹窗；恢复后只补当前轮最新一条已到期提醒，标明原计划时间。过往轮次不补，不自动确认任何事项。后续仍按原主时间计算。
6. 提醒去重独立于面板是否打开。连续 tick、重启、重复唤醒及系统时钟回拨不能重复产生同一提醒；下一轮开始后清除上一轮未确认消息。
7. 存储损坏、历史配置不合法或时区变动造成跨轮风险时，不崩溃、不执行越界提醒，并向用户显示可操作的错误提示。

## 二、接口与交互设计

本功能是本机 SwiftUI/AppKit 交互，无远端 API、账号、角色权限或服务器依赖。

1. 打开设置中的“连环提醒”，空态说明适用场景，并提供新增按钮。
2. 输入主提醒内容及每日时间，使用“添加后续提醒”连续增加步骤。每步填写内容与距前一步的正整数分钟数，旁边显示累计后的预计时间及跨日标记。
3. 修改在草稿中进行；“取消”放弃草稿。“保存”只在有效时可用，非法字段与跨轮风险显示具体原因；输入不可解析的文字时不能沿用旧数值保存。
4. 列表可编辑、启停、删除，显示下一次主时间及间隔摘要。长内容允许换行和滚动；中英文均适配 560 × 480 设置窗口。
5. 到期弹出与休息提醒同风格的面板（波点底、番茄仔、内容、时刻、“知道了”），多组同时到期时先显示最新一条并标注“还有 N 条”；点击“知道了”或按 Esc 关闭该条。护眼面板可同时出现，位置避让。

内部接口：`ReminderChainStore` 统一承担保存和启用校验；`ReminderChainScheduler` 负责启动、轮询、确认与关闭；界面不得直接写 UserDefaults 绕过校验。异常通过可显示的错误信息返回，失败保留编辑草稿。

## 三、后台数据库设计

无后台数据库，沿用项目的 JSON + UserDefaults 本地持久化方式，新增独立存储键，不改原有护眼设置和快照。

| 编号 | 数据对象 | 新增内容 |
| --- | --- | --- |
| T1 | 提醒计划 | UUID、主提醒内容、每日小时/分钟、开关、后续步骤数组；步骤包含 UUID、内容、整数分钟间隔 |
| T2 | 运行状态 | 配置生效的主时间、单计划处理进度、待确认消息与所属轮次，用于重启恢复和去重 |

旧版本没有这些键时初始化为空。读取时再次验证形状和时间边界，损坏内容不能导致崩溃或无限补提醒。归档无法解析时显示错误，保留原数据，并在下一次新建保存前备份。配置键为 `reminderChains.v1`，运行键为 `reminderChainRuntime.v1`，恢复备份键为 `reminderChains.recoveryBackup.v1`。

去重记录按计划和轮次分别保留最近 400 轮，系统日期误调到未来再纠正不会压住当前日期的正常提醒。调度使用距离最近事件的单次 Timer；没有有效启用计划时不安装 Timer，系统时钟、时区与唤醒事件重新计算。

用户输入只保存在本机，不添加网络请求或诊断导出。回退旧程序后新数据保留，旧程序不执行新提醒；不迁移、重算原有番茄数据。
